# Миграции БД (версионные)

Прод и CI применяют **версионные миграции** из этой папки — воспроизводимо и ревьюабельно,
вместо `drizzle-kit push --force` (который силой подгонял схему).

## Как это работает
- Схема — `src/shared/db/schema.ts` (источник правды).
- `npm run db:generate` — сгенерировать новую миграцию из изменений схемы (offline, БД не нужна).
- `npm run db:migrate` — применить непринятые миграции (трекинг в `drizzle.__drizzle_migrations`).
- В Docker миграции гоняет one-shot сервис `migrate` (стадия `migrate` в Dockerfile) перед стартом `app`.

## Локальная разработка
Для быстрой итерации можно `npm run db:push` (прямая синхронизация схемы, без файла миграции).
Но всё, что уедет в прод, должно быть зафиксировано `db:generate` и закоммичено сюда.

## Важно
- **pgvector**: `0000_init.sql` создаёт `CREATE EXTENSION IF NOT EXISTS "vector"` первым стейтментом —
  без него `vector(1536)`/HNSW-индекс падают на свежей БД. Не удаляйте эту строку.
- **Существующая dev-БД** (создана через `push`, без таблицы трекинга): `db:migrate` попытается
  применить `0000` и упадёт на «таблица уже существует». Такую БД нужно один раз забейзлайнить
  (пометить `0000` применённой) или пересоздать. Свежий прод-деплой применяет миграции чисто.

Проверено: `db:migrate` на чистой БД → 25 таблиц + расширение vector, `[✓] applied successfully`.
