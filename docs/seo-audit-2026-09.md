## Работа 1. Русская версия невидима для поисковиков ⚠️ критическое

**Что не так.** Русский интерфейс отдаётся **по тому же URL**, по заголовку
`Accept-Language`. Отдельных адресов нет: `setfork.com/ru` → **404**.

**Проверено тем, что видят роботы:**

```
Googlebot   → lang="en", «SetFork — versioned, runnable lists»
YandexBot   → lang="en", «SetFork — versioned, runnable lists»   ← русского не видит
браузер ru  → lang="ru", «SetFork — версионируемые запускаемые списки»
```

**YandexBot не шлёт `Accept-Language`** и всегда получает английскую версию.

**Почему это стоит трафика.** Поисковик индексирует **один вариант на один
адрес**. Русского SetFork в индексе нет и быть не может: ни заголовков, ни
описаний, ни текстов списков. Русский рынок закрыт целиком, и любая работа над
русским контентом до этой правки не окупится.

**Где в коде:** `src/shared/i18n/negotiate.ts` (разбор заголовка, сам по себе
корректный), `src/shared/i18n/server.ts`, `src/app/layout.tsx`, `src/app/sitemap.ts`.

**Что сделать:**

1. **Развести адреса по языкам** — подпапкой: `/ru/...` и либо `/en/...`, либо
   английский в корне. Next.js это умеет штатно.
2. **`Accept-Language` оставить только для первого захода** — как подсказку,
   куда перенаправить гостя, а не как способ отдавать разный контент по одному
   адресу. **Редирект с корня по языку допустим**, если у пользователя остаётся
   явный переключатель и выбор запоминается.
3. **`hreflang` на каждой паре страниц**, взаимно, плюс `x-default`.
   Оговорка: Яндекс поддерживает `hreflang`, но **не между доменами** — для
   подпапок работает.
4. **Оба языка в `sitemap.ts`** — сейчас русских адресов в карте нет вовсе.
5. **`canonical` — на свой язык**, а не общий на корень: иначе русские страницы
   объявят себя копиями английских.

**Как проверить, что сделано:**

```bash
curl -sI https://setfork.com/ru/ | head -1                      # 200, не 404
curl -s -A "YandexBot/3.0" https://setfork.com/ru/ | grep -o 'lang="[^"]*"'   # lang="ru"
curl -s https://setfork.com/sitemap.xml | grep -c "/ru/"        # больше нуля
curl -s https://setfork.com/ru/ | grep -c hreflang              # не ноль, взаимно
```

Плюс в Вебмастере через 2–3 недели: русские адреса появились в «Страницах в
поиске».

## Работа 2. Нет разметки на главной и служебных страницах

**Что не так.** `application/ld+json` в HTML главной — **ноль**. При этом
инструмент в проекте **уже есть**: `src/shared/seo/jsonld.tsx` с готовыми
`breadcrumbList`, `itemList`, `creativeWork`, и он подключён на страницах
`[handle]/[slug]`, `[handle]`, `tags/[slug]`.

То есть разметка сделана для списков, но **не для сайта как такового**.

**Почему это стоит трафика.** Сниппет беднее, чем у конкурентов; нет строки
поиска по сайту прямо в выдаче; и — важнее в 2026 — **разметка нужна для
попадания в ответы нейросетей**, а не только ради вида в выдаче.

**Что сделать** — добавить в `src/app/layout.tsx` или отдельным компонентом:

| Схема | Что даёт |
|---|---|
| `Organization` | кто стоит за продуктом, логотип в выдаче |
| `WebSite` | название сайта в выдаче. **`SearchAction` не нужен:** поле поиска под результатом Google убрал 21.11.2024 |
| `SoftwareApplication` | продукт: категория, платформа, цена (в том числе бесплатно) |

И отдельно — **по типам списков**:

| Схема | Где | Почему именно здесь |
|---|---|---|
| **`Recipe`** | на рецептах | единственный из типов корпуса, у которого в Google **живой** расширенный сниппет: время, ингредиенты, картинка в выдаче |
| `HowTo` | на страницах списков с шагами | сниппета в Google **нет с сентября 2023**. Ставить ради нейроответов и других потребителей словаря — но не как работу, которая даст вид в выдаче |

> **Поправка 23.09.** В первой версии здесь стояли `HowTo` как «совпадение, которое стоит
> занять первым» и `FAQPage` «ради быстрых ответов». Google снял сниппет `HowTo` в сентябре
> 2023, а `FAQPage` — 7 мая 2026: в выдаче Google обе разметки больше ничего не дают.
> `FAQPage` убран, `HowTo` понижен, добавлен `Recipe`. Там же: `SearchAction` у `WebSite`
> больше ничего не даёт — поле поиска в выдаче Google убрал 21.11.2024.

**Как проверить:**

```bash
curl -s https://setfork.com | grep -c "application/ld+json"     # ≥ 1
```

Плюс валидатор Rich Results Test на главной и на странице списка — без ошибок;
валидатор Яндекса в Вебмастере — тоже.

## Работа 3. Нет `og:image`

**Что не так.** Открытые графы есть (`og:title`, `og:description`, `og:type`,
`og:url`), **картинки нет**.

**Почему это стоит трафика.** Каждая ссылка на SetFork в Телеграме, Слаке,
Дискорде разворачивается серым прямоугольником. Для продукта, который
распространяется ссылками между разработчиками, это **прямая потеря переходов**
— и потеря там, где трафик самый тёплый.

**Что сделать.**

1. Статическая `og:image` 1200×630 для главной и служебных страниц.
2. **Динамическая для каждого списка** — с названием на картинке. В Next.js это
   `ImageResponse` из `next/og`, генерация на лету.

> **Заодно проверяется свой инструмент:** favimaker
> умеет собирать `og-image.png` 1200×630 — ровно эта задача. Хороший повод
> убедиться, что он годится в деле, а не только на витрине.

**Как проверить:**

```bash
curl -s https://setfork.com | grep -o 'og:image[^>]*'           # есть
```

Плюс вставить ссылку в Телеграм — разворачивается с картинкой.

## Работа 4. `H1` главной — просто «SetFork»

**Что не так.** Заголовок первого уровня несёт только имя бренда.

**Почему это стоит трафика.** `H1` — самый весомый текстовый сигнал страницы.
Сейчас он не сообщает поисковику, что продукт делает. Для навигационных
запросов («setfork») этого достаточно, для всех остальных — нет.

**Что сделать.** Оставить логотип как есть визуально, но в `H1` вынести
осмысленную формулировку — ту же, что в `title`, или короткое описание задачи,
которую продукт решает. Правка на пятнадцать минут.

**Как проверить:** `H1` содержит не только слово «SetFork», и он ровно один на
странице.

## Работа 5. `Host` в `robots.txt`

**Что не так.**

```
Host: https://setfork.com
```

Директива **отменена Яндексом в марте 2018**. Склейка зеркал делается
301-редиректом и разделом «Переезд сайта» в Вебмастере.

**Почему стоит убрать.** Вреда нет, но это маркер: «файлом давно никто не
занимался». На собственном продукте такое оставлять неловко — особенно если
файл потом покажут как пример работы.

**Где:** `src/app/robots.ts`.

**Как проверить:** `curl -s https://setfork.com/robots.txt | grep -c Host` → 0.

## Работа 6. `cache-control: no-store` на главной — разобраться

**Что наблюдается.**

```
cache-control: private, no-cache, no-store, max-age=0, must-revalidate
```

Главная полностью запрещена к кешированию.

**Почему это может стоить трафика.** Скорость прямо влияет на поведенческие
факторы, а `no-store` означает, что страница собирается заново на каждый заход,
в том числе для гостя, который видит одно и то же.

**Но это не обязательно ошибка.** Если на главной есть персонализация —
состояние входа, свои списки, — запрет оправдан.

**Что сделать:** разобраться, различается ли главная для гостя и вошедшего.
Если для гостя она одинакова — отдавать её с кешированием (в Next.js это
разделение на статическую оболочку и динамические участки).

**Как проверить:** заголовок ответа для анонимного запроса допускает
кеширование, а страница для вошедшего по-прежнему приватна.
