# Пагинация

План развития листания живёт в HQ: **`setfork-hq/tracks/pagination.md`** — там состояние по
поверхностям, зафиксированные решения, пороги переключения механики и фазы. Все пять фаз
закрыты 19.08.2026; трек остаётся источником решений, а не списком работ.

## Две механики, и выбор между ними не по вкусу

**Номера страниц** — у каталогов: задачи, правки, обсуждения, релизы, прогоны, списки
профиля, полка, теги. По каталогу ПРЫГАЮТ («открыть страницу 7», «уйти на последнюю»), и
номер — единственное, что это умеет. Платой идёт дрейф: при сортировке «сначала новые»
свежая строка встаёт сверху, и строка с границы может прийти на следующую страницу
второй раз. Это принятая цена, а не недосмотр.

**Курсор (keyset)** — у лент, читаемых сверху вниз: уведомления, треды задач, правок и
обсуждений, история версий списка, журнал аудита. Там смещение даёт не медленную выдачу,
а НЕВЕРНУЮ — начало отсчёта уезжает, пока ленту читают. Прыжка на порцию N курсор не
умеет, но лентам он и не нужен.

## Правила, за которыми следят тесты

- **У упорядоченной выдачи есть предел.** `tests/architecture/paging-discipline` —
  исключения только для ограниченного природой сущности, у каждого записана причина.
- **Ссылку на страницу строит только `pageHref`.** Там же. Рукописный `?page=` теряет
  остальные параметры, и со второй страницы у человека молча слетает отбор.
- **Порядок индекса совпадает с `ORDER BY`, включая место NULL.**
  `tests/architecture/index-nulls-order`: `.desc()` у drizzle строит `DESC NULLS LAST`, а
  `ORDER BY x DESC` значит `NULLS FIRST` — не совпало, и индекс не годится для сортировки
  вовсе, молча.
- **У keyset-порядка есть поддерживающий индекс.**
  `tests/features/library/keyset-indexes.itest`: без него курсор не даёт ничего — база
  читает и сортирует весь тред на каждую порцию.
- **Шаблон поиска строит только `likeContains`.** `tests/architecture/like-escaping`:
  иначе `%` и `_` работают как язык шаблонов, и поиск по проценту отдаёт всё.

## Рецепт: добавить листание на новую поверхность

1. Решить по форме данных: каталог (номера) или лента (курсор).
2. Каталог: окно через `feedWindow`, счёт по ТЕМ ЖЕ условиям, что и выдача — одной
   функцией на обе, иначе листалка нарисует несуществующие страницы.
3. Лента: `keysetStep` + `cursorKey` + `keysetPage`, разбор адреса — `readCursor`.
4. Порядок ВСЕГДА доопределён до `id`.
5. Индекс под порядок — иначе смысла нет.
6. Тест от симптома, и **мутация на этот тест**: снять правку, убедиться, что он
   покраснел. Проверка, не проверенная мутацией, доказывает только то, что компилируется.
