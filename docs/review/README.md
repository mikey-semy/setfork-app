# Сплошное ревью SetFork

Состояние ревью живёт **на диске, а не в переписке**. Сессия, которая ничего не знает,
выполняет одну команду и видит полную картину.

```sh
npm run review:status     # где мы и какой блок следующий
npm run review:coverage   # карта «файл → блок»; падает, если файл ничей
npm run review:check      # манифесты на месте, шаблоны путей не пустые
npm run review -- prompt H1 --role hunter   # готовый промпт агенту
```

## Устройство

| файл | что это |
|---|---|
| `blocks.json` | из чего состоит ревью: 28 блоков, их файлы. Правится руками |
| `state.json` | как далеко зашёл каждый блок. Правится инструментом |
| `invariants.md` | **правила SetFork.** Вклеиваются каждому агенту; от них зависит, что он сочтёт дефектом |
| `blocks/<ID>-<слаг>.md` | манифест блока: зачем, что находка, гипотезы, критерий приёмки |
| `findings.jsonl` | реестр находок, по строке на находку |
| `coverage.tsv` | карта покрытия, пересобирается |
| `prompts/` | три роли: охотник, проверяющий, исполнитель |

## Порядок работы над блоком

1. **Манифест.** Написать `blocks/<ID>-<слаг>.md` — без проектных гипотез ревью выйдет «по
   общим соображениям». Образец: `blocks/H1-access.md`.
2. **Охотник** (`--role hunter`) читает файлы блока и выдвигает находки.
3. **Проверяющий** (`--role verify`) проверяет каждую по текущему коду и делает свой
   независимый проход. Отвергнутые находки **не удаляются** — остаются с причиной отказа,
   иначе следующее ревью найдёт то же самое.
4. **Приёмка.** Прочитать отчёты самому и сверить с критерием приёмки блока. Охват неполный —
   вернуть на повторный проход, а не закрывать.
5. **Починка** (`--role fix`) — **другим** агентом, не тем, кто искал.
6. **Ревью диффа** — теми, кто его не писал, **до** открытия предложения.

⚠️ Один агент не ищет и не чинит одновременно. ⚠️ Блок не закрывается без выполненного
критерия приёмки.

## Три фазы

**Сквозные** (H1–H13) идут первыми: они задают язык. Когда блок доступа выписал таблицу
«маршрут → гейт», доменные блоки читают код, уже зная границы.
**Доменные** (V1–V12) читают свой срез целиком — от миграции до экрана.
**Стендовые** (S1–S3) файлами не владеют: работают на запущенной системе.

## Как это заканчивается

Когда блоки закрыты и открытых находок нет, `docs/review/` **удаляется целиком одним
предложением**, а долговечное переезжает туда, где живёт по-настоящему: правила — в
`CONTRIBUTING.md` и `AGENTS.md`, решения — в HQ, проверки — в тесты и узды CI. Каталог ревью
— это леса вокруг стройки, а не часть здания.

Набор взят у соседнего проекта; его описание — `setfork-hq/tools/review-kit/`.

## Сколько это стоит

Оценка **до первого прогона**, по числам соседнего проекта (`dnl-viewer`, блок H1) — то есть
косвенная. Первый же наш блок её уточнит, и тогда эти числа надо переписать.

Что известно по факту оттуда: блок H1 — **7 файлов, 1727 строк**, шесть запусков агентов,
2 ч 10 мин, 33 находки. Весь цикл блока с кругами перепроверки — **15 агентов**, каждый
**300–450 тыс. токенов** (среднее ≈ 370 тыс.), плюс ведущая сессия ≈ 400 тыс.

**≈ 6 млн токенов на один блок в 1727 строк.**

Считать удельно «на строку» нельзя: цена растёт не от объёма, а от **числа кругов**, а круги
зависят от того, сколько нашлось. H1 был блоком доступа — 33 находки на 1727 строк, плотность
исключительная. Поэтому честнее считать по агентам:

| род блока | агентов | ориентир |
|---|---:|---:|
| лёгкий: охотник + проверяющий, находок мало | 2–3 | ≈ 1 млн |
| средний: + исполнитель + ревью диффа | 5–6 | ≈ 2 млн |
| тяжёлый: три круга «починил → проверили» | 15 | ≈ 5,5 млн |

У нас **39 блоков**. Если 8 тяжёлых, 16 средних, 15 лёгких — **порядка 90 млн токенов** на
полный проход. Это месяцы, а не недели, и полный проход подряд смысла не имеет.

**Отсюда порядок работы: по риску, а не по списку.** Круги вести только там, где дефект
дорого стоит; мелкие блоки сводить в один заход. Первые пять по риску:

1. **H1** — доступ и видимость: утечка приватного необратима.
2. **H15** — доменное ядро: правила, на которые опирается всё остальное.
3. **V1d** — запись и версии: порча чужого списка, и её не откатить со страницы.
4. **H5** — деньги и квоты: чужие деньги.
5. **H4** — поверхность MCP: оплачивается пользователем на каждом запросе.

Пять блоков ≈ 20 млн токенов — это неделя-две, а не месяцы.
