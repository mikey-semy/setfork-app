# Деплой и персистентность (Dokploy)

Прод-стек — [`docker-compose.dokploy.yml`](../docker-compose.dokploy.yml): Postgres +
Rust git-ядро + миграции + фронт (+ опц. свой Stalwart-mail). Медиа (S3/imgproxy) —
внешние (Selectel). Роутинг на `app:3000` — ярлыками Traefik в UI Dokploy.

## Персистентные тома — что нельзя потерять

Именованные тома переживают redeploy/recreate; исчезают только при `down -v` или ручном
удалении. Каждый **stateful**-сервис имеет свой том:

| Том (dokploy) | Сервис | Что внутри | Потеря = |
|---|---|---|---|
| `pgdata` | `db` | вся БД: юзеры, списки, issues, токены, аудит | катастрофа (см. бэкапы) |
| `setfork_git` | `core` | bare-репозитории — **источник правды** git-объектов | теряются точные запушенные SHA (историю можно пересобрать из БД, но не хеши) |
| `stalwart` | `mail` | конфиг/очереди почтового сервера | переспросить DKIM/аккаунты |

Медиа-**uploads тома нет намеренно**: оригиналы лежат во внешнем S3 (Selectel) с его
надёжностью. Локальный `docker-compose.yml` для dev держит их в томе `miniodata`.

> ⚠️ В Dokploy проверьте, что тома созданы как **named volumes** (не anonymous) — иначе
> «recreate» их обнулит. Имена выше должны быть видны в `docker volume ls`.

Резервное копирование и восстановление этих томов — [backups.md](./backups.md)
(cron + offsite + проверка рестора). Бэкапы покрывают `pgdata` и `setfork_git`.

## CDN перед imgproxy

imgproxy отдаёт подписанные трансформации на лету — их нужно кэшировать на CDN, а не
бить в imgproxy каждым запросом:

```
браузер → CDN (кэш по URL) → imgproxy → S3-оригинал
```

- `CDN_URL` — публичный базовый URL CDN (например, CDN Selectel перед вашим imgproxy).
  Задан → `avatarSrc`/медиа-хелперы строят ссылки через него; пусто → напрямую в `IMGPROXY_URL`.
- Подписи imgproxy (`IMGPROXY_KEY`/`IMGPROXY_SALT`) неизменны при добавлении CDN — тот же
  URL просто кэшируется. Инвалидация не нужна: трансформации иммутабельны (ключ в пути).
- Настройте на CDN длинный `Cache-Control`/TTL для путей imgproxy.

## Почта — опциональна и выключена по умолчанию

Сервис `mail` (Stalwart) спрятан за **compose-профилем `mail`** и НЕ поднимается при
обычном `docker compose up` — почта в приложении необязательна (пустой SMTP = отключена),
и mail не должен блокировать деплой фронта. Включить, когда будете настраивать SMTP:

```sh
docker compose -f docker-compose.dokploy.yml --profile mail up -d
```

> Образ переименован: `stalwartlabs/mail-server` → **`stalwartlabs/stalwart`** (у старого
> репо больше нет тега `latest`). Запинен на `v0.16.11`; данные — том `stalwart` в `/opt/stalwart`.

## Хардненинг после первого старта

- **Обязательно задайте секреты в окружении Dokploy** (Environment проекта): `POSTGRES_PASSWORD`
  (иначе Postgres стартует с пустым паролем и падает), а также VAPID, SMTP, S3, `IMGPROXY_*`.
  Compose интерполирует `${...}` из этого окружения — предупреждение «variable is not set»
  означает, что переменная там не задана.
- Секреты — только в окружении/`.env` на хосте, не в git. `ADMIN_HANDLES` без `demo` в проде.
- **Порт веб-админки почты `:8080`** (только при включённом профиле `mail`) открыт для разовой
  настройки Stalwart — после настройки **закрыть** фаерволом или убрать проброс порта.
- Прочие плавающие теги (`minio:latest`) стоит запинить для воспроизводимых деплоев.

## Моно-чекаут

`core` собирается из соседнего `../setfork-core` — при деплое оба репозитория должны
лежать рядом. Альтернатива — деплоить ядро отдельно его же compose и указать
`SETFORK_CORE_ADDR=setfork-core:50051`, убрав сервис `core` здесь.
