# Деплой и персистентность

> Обновлено 19.08.2026. Прежняя редакция описывала деплой через панель **Dokploy** — её
> сняли 13.08.2026 вместе со Swarm, и с тех пор выкаткой управляет CI. Имя файла
> `docker-compose.dokploy.yml` осталось историческим: это просто базовый compose прода.

Прод-стек — [`docker-compose.dokploy.yml`](../docker-compose.dokploy.yml): Postgres +
Rust git-ядро + миграции + фронт (+ опц. свой Stalwart-mail). Медиа (S3/imgproxy) —
внешние (Selectel). Сеть одна — `edge`, обычная bridge.

## Кто и как катит

Джоба `deploy` в [`.github/workflows/ci.yml`](../.github/workflows/ci.yml), только на
push в `master` (и вручную через `workflow_dispatch`). Панели нет, всё по SSH:

1. `check` → `integration` → `image` обязаны позеленеть — `deploy` идёт за ними по
   `needs`, то есть непроверенное на прод не уезжает;
2. `image` публикует в GHCR два образа с тегами `app-<sha>` и `migrate-<sha>`;
3. `deploy` заливает дерево репозитория на сервер, СОХРАНЯЯ с прежнего `.env` и
   `docker-compose.override.yml` (в нём весь traefik-роутинг `.com`; без него сайт уходит
   в 404 — на это стоит явная проверка), пишет `docker-compose.image.yml` с тегами и
   поднимает `docker compose up -d --no-build` тремя файлами разом;
4. Health-check ждёт, пока контейнер фронта станет здоровым, и валит джобу, если не стал.

**Ключ деплоя** монтируется в раннеры из `setfork-ci-runner/.env` (`SSH_KEY`). Если он
указывает на пустую заглушку `.deploy-key-placeholder`, то `check`/`integration`/`image`
зелёные, а `deploy` падает на `ssh -i` — прод при этом ЦЕЛ, выкатка просто не происходит.

**Доступ к GHCR** нужен и раннеру (тянет образ ядра для `integration`), и прод-серверу
(тянет образы приложения). На сервере логин делает сама джоба и выходит после.

## Как узнать, что выкатка прошла

- **Красный деплой** заводит issue «🔴 Деплой на прод падает» в этом же репозитории и
  комментирует её при повторах; зелёная выкатка закрывает тревогу сама.
- **Успешная выкатка** шлёт оповещение в ntfy (переменная репозитория
  `NTFY_DEPLOY_URL`), по желанию — в телеграм (секреты `TELEGRAM_BOT_TOKEN`,
  `TELEGRAM_CHAT_ID`, база — переменная `TELEGRAM_API_BASE`). Ничего не задано — в логе
  предупреждение: сигнальный механизм не должен умирать молча.

Почему ntfy, а не телеграм основным: раннер стоит в РФ, где `api.telegram.org` закрыт по
SNI, и приложение ходит к нему через egress-мост. Оповещение о деплое, зависящее от того
же моста, замолчало бы ровно тогда, когда с инфраструктурой плохо.

## Персистентные тома — что нельзя потерять

Именованные тома переживают redeploy/recreate; исчезают только при `down -v` или ручном
удалении. Каждый **stateful**-сервис имеет свой том:

| Том | Сервис | Что внутри | Потеря = |
|---|---|---|---|
| `pgdata` | `db` | вся БД: юзеры, списки, issues, токены, аудит | катастрофа (см. бэкапы) |
| `setfork_git` | `core` | bare-репозитории — **источник правды** git-объектов | теряются точные запушенные SHA (историю можно пересобрать из БД, но не хеши) |
| `stalwart` | `mail` | конфиг/очереди почтового сервера | переспросить DKIM/аккаунты |

Медиа-**uploads тома нет намеренно**: оригиналы лежат во внешнем S3 (Selectel) с его
надёжностью. Локальный `docker-compose.yml` для dev держит их в томе `miniodata`.

> ⚠️ Тома обязаны быть **именованными** (не anonymous) — иначе «recreate» их обнулит.
> Имена выше должны быть видны в `docker volume ls` на прод-сервере.

Резервное копирование и восстановление этих томов — [backups.md](./backups.md)
(cron + offsite + проверка рестора). Бэкапы покрывают `pgdata` и `setfork_git`.

## CDN перед imgproxy

imgproxy отдаёт подписанные трансформации на лету — их нужно кэшировать на CDN, а не
бить в imgproxy каждым запросом:

```
браузер → CDN (кэш по URL) → imgproxy (:8081) → S3-оригинал (Selectel)
```

- **imgproxy self-hosted** в `docker-compose.dokploy.yml` (сервис `imgproxy`, порт `8081`):
  читает оригиналы из внешнего S3 (те же креды `S3_*`, что у приложения). CDN Selectel
  ставится **перед** ним (origin CDN = `http://<vps>:8081` или ваш `img.<домен>:8081`).
- ⚠️ **`CDN_URL` и `IMGPROXY_URL` должны включать схему `https://`.** Код строит URL как
  `${base}/${подпись}${путь}`, где `base = CDN_URL || IMGPROXY_URL`. Значение без схемы
  (напр. `f3b98df8-….selcdn.net`) даст относительный, сломанный URL — нужно
  `https://f3b98df8-….selcdn.net`.
- `CDN_URL` задан → медиа-хелперы строят ссылки через CDN; пусто → напрямую в `IMGPROXY_URL`.
- Медиа-настройки берутся из БД (`/admin` → «Хранилище и изображения»), env — фолбэк/сид.
  То есть проще один раз выставить их в админке, чем в env.
- Подписи imgproxy (`IMGPROXY_KEY`/`IMGPROXY_SALT`) неизменны при добавлении CDN — тот же
  URL просто кэшируется. Инвалидация не нужна: трансформации иммутабельны (ключ в пути).
- Настройте на CDN длинный `Cache-Control`/TTL для путей imgproxy.

## Почта — опциональна и выключена по умолчанию

Сервис `mail` (Stalwart) спрятан за **compose-профилем `mail`** и НЕ поднимается при
обычном `docker compose up` — почта в приложении необязательна (пустой SMTP = отключена),
и mail не должен блокировать деплой фронта. Включить, когда будете настраивать SMTP:

```sh
docker compose -f docker-compose.dokploy.yml --profile mail up -d
```

> Образ переименован: `stalwartlabs/mail-server` → **`stalwartlabs/stalwart`** (у старого
> репо больше нет тега `latest`). Запинен на `v0.16.11`; данные — том `stalwart` в `/opt/stalwart`.

## Хардненинг после первого старта

- **Секреты живут в `.env` рядом с compose на прод-сервере**: `POSTGRES_PASSWORD`
  (иначе Postgres стартует с пустым паролем и падает), а также VAPID, SMTP, S3,
  `IMGPROXY_*`. Compose интерполирует `${...}` оттуда — предупреждение «variable is not
  set» означает, что переменная не задана. Этот `.env` переносится при каждой выкатке с
  прежнего дерева, и его отсутствие останавливает деплой явной ошибкой.
- Секреты — только в окружении/`.env` на хосте, не в git. `ADMIN_HANDLES` без `demo` в проде.
- **Порт веб-админки почты `:8080`** (только при включённом профиле `mail`) открыт для разовой
  настройки Stalwart — после настройки **закрыть** фаерволом или убрать проброс порта.
- Прочие плавающие теги (`minio:latest`) стоит запинить для воспроизводимых деплоев.

## Моно-чекаут

`core` собирается из соседнего `../setfork-core` — при деплое оба репозитория должны
лежать рядом. Альтернатива — деплоить ядро отдельно его же compose и указать
`SETFORK_CORE_ADDR=setfork-core:50051`, убрав сервис `core` здесь.
