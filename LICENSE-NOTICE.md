# Почему приложение НЕ под открытой лицензией

`setfork-frontend` — само приложение SetFork. Лицензия **проприетарная**.

## Почему не Apache и не MIT

Permissive-лицензия разрешает взять приложение, **закрыть** его и поднять
конкурирующий хостинг, ничего не возвращая. Для продукта, который мы собираемся
монетизировать, это отдаёт ровно то единственное, что трудно скопировать, —
работающую реализацию.

Ровно поэтому GitHub закрыт, GitLab — open-core, а полностью открытые Gitea и
Forgejo прекрасны, но никем толком не монетизируются.

## Почему не «просто без файла»

Отсутствие лицензии — не нейтральное состояние: по умолчанию это всё равно «все
права защищены», только молча. Худшая комбинация — код видно, использовать
нельзя, и никто не понимает правил. Явный файл снимает неопределённость.

## Что открыто

- **Ядро** (`setfork-core`) — AGPL-3.0: им можно пользоваться, закрыть форк
  нельзя.
- **Формат списка** (`list.json`, идентичность блоков) — спецификацию имеет
  смысл выпустить permissive отдельным репозиторием, когда она будет вынесена:
  формат не конкурентное преимущество, а точка притяжения интеграций.

## Если решим открыть приложение

Тогда **не** MIT/Apache, а одно из двух:

- **AGPL-3.0** — правки обязаны публиковаться, в том числе при работе по сети;
- **BUSL-1.1 / FSL** — прямой запрет конкурирующего сервиса на 2–4 года, затем
  переход в Apache/GPL. Это ответ на страх «поднимут клон».

История репозитория проверена на секреты (2026-07-28): `.env` никогда не
коммитился, совпадений по шаблонам ключей нет. Открыть можно будет без
переписывания истории.
